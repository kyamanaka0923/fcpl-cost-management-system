## 要件と満たし方

| 要件 | 判定する金額 | API | 処理ルール |
|---|---|---|---|
| FR-4.8 | 明細の半期一括の金額 | `PUT /api/budgets/{budgetId}/lines`(`UpsertBudgetLineRequest.amount`) | 下の「判定」の 0 以上 |
| FR-4.10 | 明細の半期一括の金額 | 同上 | 下の「判定」の 1 円単位 |
| FR-4.11 | 明細の月別金額(月インデックス 1..6) | 同上(`UpsertBudgetLineRequest.monthlyAmounts` の各値) | 下の「判定」の 0 以上 |
| FR-4.12 | 明細の月別金額(月インデックス 1..6) | 同上 | 下の「判定」の 1 円単位 |
| FR-6.7 | 実績の計上金額(半期一括・月別の両方) | `POST /api/departments/{id}/actuals`(`RecordActualRequest.amount`) | 下の「判定」の 0 以上 |
| FR-6.8 | 実績の計上金額(半期一括・月別の両方) | 同上 | 下の「判定」の 1 円単位 |

- 判定する金額は、この 3 種類(半期一括の金額・月別金額・計上金額)だけ。3 種類に同じ判定を使う(BR-BUD-007)。
  実装は 1 つの判定をドメイン層に置き、3 か所から呼ぶ
- 判定はドメイン層で行い、外れたときは `DomainException` を投げる。WebApi が 400 と `ErrorResponse`(`error` に文言)に変換する(いまの `Program.cs` の変換のまま)
- 画面の入力欄のふるまいは [SPEC-002](SPEC-002.md)。この判定は、画面を通らずに届いた金額のためにもある(BR-BUD-007、OQ-006 の回答)

## ルール

### 判定

```
受け付ける ⇔ 金額 ≥ 0 かつ 金額 = ⌊金額⌋
```

| # | 金額 ≥ 0 | 金額 = ⌊金額⌋ | 判定 | HTTP | 文言 |
|---|---|---|---|---|---|
| 1 | はい | はい | 受け付ける | 200 / 201 | — |
| 2 | はい | いいえ | 拒否する | 400 | 金額は1円単位の整数で入力してください。 |
| 3 | いいえ | はい | 拒否する | 400 | 金額は0以上で入力してください。 |
| 4 | いいえ | いいえ | 拒否する | 400 | 金額は0以上で入力してください。 |

- 行 4(両方に外れる値。例 -0.5)は、0 以上の判定の文言を出す(BR-BUD-007)。
  実装の順序は「0 以上」→「1 円単位」の順に判定する
- 判定するのは**値**であって、JSON での書き方ではない。`100.0` は ⌊100.0⌋ = 100.0 なので行 1(受け付ける)。
  `100` と `100.0` と `1.0E2` は同じ値として同じ判定になる
- 「金額は0以上で入力してください。」はいまのドメインの `DomainException` の文言。
  「金額は1円単位の整数で入力してください。」は #46 で新しく決めた文言(BR-BUD-007、`.feature` の `ならば` と一字一句同じ)

### 拒否したときの状態

- 1 回の要求で拒否したときは、その要求の金額を 1 つも保存しない。保存されている明細の金額・月次・実績は、その要求の前のまま
  (FR-4.11・FR-4.12 の補足、BR-BUD-005)
- 月別金額は、全件を判定してから書き換える(1 つでも外れたら、同じ要求のほかの月の金額も保存しない)
- 1 回の要求で 2 つ以上の金額が判定に外れたときは、そのうち 1 つの文言で 400 にする。どの金額の文言を出すかは決めない
  (要件に決まりがない。テストは、この場合に文言を 1 つに決めつけない)

- 具体例の 9 行(`100.0`)は、JSON の数値として `100.0` を送る API E2E ではなく、単体(Domain)で `100.0m` を渡して確かめる。
  JSON の書き方による差がないことは、同じ値なら同じ判定になる(上の「判定」)ことから導かれる
- `.feature` のシナリオ(`@未実装` を含む)は要件の成果物なので、この仕様では変えない

## WebAPI 仕様(`docs/api/openapi.json`)

変えない。理由は次の 3 つ。

1. `docs/api/openapi.json` は実装から生成したものと一致することをテスト(`tests/e2e/api/OpenApiDocumentTests.cs`)が確かめる。
   手で `minimum` や `multipleOf` を足しても、生成元のコード(`decimal` の引数)から同じものは出ないため、一致しなくなる
2. 要件は拒否のしかたを「400 と日本語の文言」で決めている(`.feature` が `ErrorResponse.error` の文言を検証する)。
   スキーマの制約で拒否させるには、生成元に検証属性が要り、ASP.NET のモデル検証が別の形の 400 を返すため、決めた文言と合わない
3. 金額は値として判定する(`100.0` は受け付ける)。型を `integer` に変えることは、この判定とは別の話で、要件にない
