# ADR-0011: テスト戦略(多層テスト + カバレッジ + ミューテーションテスト)

- 状態: Accepted
- 日付: 2026-07(ミューテーションは Issue #6)

## 背景

業務ルールの正しさと、それを検証するテスト自体の有効性の両方を担保する必要があった。
行カバレッジは「コードを実行したか」しか見ず、「テストが仕様を実際に検証しているか」は測れない。

## 決定

- バックエンドは **5 種のテスト**で構成する: Domain(不変条件・計算規則)/ Application(ユースケース、一時 SQLite)/
  Infrastructure(永続化往復・スキーマ作り直し)/ E2E(WebApplicationFactory 経由の HTTP)/ Architecture(NetArchTest)。
- フロントは **ブラウザ E2E(Playwright)**(バックエンド + Vite を自動起動)。
- **テスト名・エラーメッセージ・コミットメッセージは日本語**とし、テスト一覧が仕様書として読めるようにする。
- **行カバレッジ 85% 以上**を維持し、CI(ReportGenerator)の実行サマリで可視化する(現状 89.9%)。
- **ミューテーションテスト(Stryker.NET)**で Domain・Application 層のテスト有効性を測定し、
  CI の `mutation` ジョブで markdown レポートをサマリへ、HTML をアーティファクトへ出力する。
  閾値 break:0 の**非ブロッキング運用**(スコアでは CI を落とさない)。Infrastructure/WebApi は対象外。

## 結果

- 仕様に対する検証の抜け(生存ミュータント = テストが変異を区別できない箇所)を可視化できる。
- ミューテーションは実行が遅いため、対象を中核 2 層に絞り、CI では非ブロッキングとした。
- ブラウザ E2E は単一 DB を serial 実行で共有するため、新機能の検証は独立テストに切り出す(重要フローを乱さない)。
