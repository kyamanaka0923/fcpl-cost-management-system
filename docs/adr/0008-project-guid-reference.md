# ADR-0008: 案件は GUID 参照・コードは課ごとに一意で編集可能にする

- 状態: Accepted
- 日付: 2026-07(Issue #1・#2・#3)

## 背景

案件(Project)は課に属する明細の内訳次元である。案件コードの一意性の範囲、
コード変更の可否、案件のライフサイクル状態の要否について整理が必要だった
(Issue #1: 費目/案件の所属、Issue #2: 終了ステータス、Issue #3: コード・名称編集)。

## 決定

- 他集約(`BudgetLine` / `ActualEntry`)は案件を **`ProjectId`(生成時採番の GUID)** で参照する。
- **案件コードは課ごとに一意**(別の課では同じコードを使える)。DB 制約は `UNIQUE (department_id, code)`。
  `IProjectRepository.FindByCodeAsync` は (DepartmentId, code) でスコープする。
- **案件のコード・名称は登録後も編集可能**(`Project.Edit`)。参照は GUID なのでコード変更で参照は壊れない。
  編集時も課ごとのコード一意性を Application 層で検証する(自分自身は除外)。
- **案件はライフサイクル状態(終了/Completed 等)を持たない**(Issue #2 で廃止)。

## 結果

- コード体系を課ごとに独立させつつ、名称・コードの是正を安全に行える。
- 案件は「明細の内訳次元」に徹し、予算承認で明細が確定する(案件自体の状態管理は持たない)。
- **ProjectStatus・数量的なライフサイクルは復活させない**。
