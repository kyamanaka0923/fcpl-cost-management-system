# ADR-0007: 永続化は SQLite + Dapper、旧世代スキーマは移行せず作り直す

- 状態: Accepted
- 日付: 2026-07-11(移行方針)

## 背景

本システムは単一コンテキストのモジュラーモノリスで、単一ファイルで完結する軽量な永続化が適していた。
また ADR-0002 の大規模再構築では、旧世代(プロジェクト単位)のデータを新世代(課 × 半期)へ
機械的に対応付けることができなかった。

## 決定

- 永続化は **SQLite + Dapper**。ORM の重い抽象化は使わず、リポジトリ実装で SQL を直接扱う。
  型ハンドラで Guid/decimal/DateTime ↔ TEXT を変換する。
- **旧世代スキーマからのデータ移行は行わない**。起動時に旧世代テーブルを破棄し新スキーマで作り直す
  (`DropLegacyTables`)。破棄処理は**冪等**に実装する。
- 例外として、**現世代スキーマ内の変更**(制約緩和・不要カラム削除・カラム追加など既存データが衝突しない変更)は、
  データを保持したままのマイグレーションを行う。RENAME→CREATE→INSERT SELECT→DROP をトランザクションで冪等に。
  単純なカラム追加は `ALTER TABLE ... ADD COLUMN` でよい(例: Issue #1 の一意制約変更、Issue #2 の status 廃止、Issue #5 の month 追加)。

## 結果

- セットアップが単純で、テストは一時 SQLite ファイルで高速・独立に回せる。
- サーバーレスでは書き込み直列化が必要になる(ADR-0010 で Lambda 予約同時実行 = 1)。
- 旧世代からのデータは引き継げない(再構築時の割り切り)。現世代内では冪等マイグレーションでデータを保持する。
- スキーマ変更時は `SchemaResetTests` に「旧テーブル破棄・作り直し + 冪等性 + 新スキーマデータ保持」を追加する。
