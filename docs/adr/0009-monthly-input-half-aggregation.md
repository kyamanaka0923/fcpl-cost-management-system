# ADR-0009: 明細ごとの月次入力を許容し集計は半期粒度のままにする

- 状態: Accepted
- 日付: 2026-07(Issue #5)
- 補足: 当初は「明細の時間粒度 = 半期一括」(requests/2026-07-11 論点4)だったが、Issue #5 で見直した

## 背景

半期一括だけでは月ごとの計画・実績を持てず、期中の進捗が見えにくいという要望があった。
一方で、集計・差異・損益・部集計まで月次粒度にすると分析が煩雑になり、
「課 × 半期」を管理単位とする方針(ADR-0002)と整合しなくなる。

## 決定

- 半期一括に加えて、**明細ごとに月次(半期内の月インデックス 1..6)入力**を許容する。
  - `BudgetLine` は月別金額 `MonthlyAmounts` を持ち、`IsMonthly` は月別金額の有無で判定。
    `Amount`(半期合計)は月次なら月別の合計。半期一括の Upsert で月次モードは解除される。
  - `ActualEntry` は計上月 `Month`(1..6 or null)を持つ。月の検証は `HalfMonths.Validate`。
- **集計・差異分析・損益・部集計はすべて半期粒度のまま**とする。月次は入力の内訳にすぎない。

## 結果

- 月別の計画・実績を保持しつつ、分析は半期のシンプルさを維持できた。
- 表示・集計は半期のままなので、月次の折れ線などの月次分析ビューは持たない(要件外)。
- これは requests/2026-07-11 の「半期一括のみ」という当初判断を**意図的に更新**したもの(復活時は本 ADR を更新する)。
