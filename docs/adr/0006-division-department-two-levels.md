# ADR-0006: 組織を部 > 課の2階層とし部は集計ビューにする

- 状態: Accepted
- 日付: 2026-07(部集計の追加時)
- 関連: [requests/2026-07-12-requirement-change.md](../requests/2026-07-12-requirement-change.md)

## 背景

部門長は「どの課の損益が弱いか」を配下課をまたいで把握したいという要件があった。
一方で予算を策定・承認する主体は課であり、部が独自の予算値を持つと二重管理になる。

## 決定

- 組織を **部(Division)> 課(Department)の2階層**とする。課は必ず1つの部に属する。
- **部は予算を策定しない集計ビュー**とする。部の数値は配下課の予実の合計として導出する
  (`DivisionBudgetSummaryService`)。不変条件は「部合計 = 課別内訳の合計」。
  承認済み予算のない課は合計から除外し「未策定」として内訳表示する。
- **部承認(`DivisionBudgetApproval`)** は (部, 半期) ごとの独立集約(レコードの有無 = 承認状態)。
  配下の全課が承認済みのときのみ承認可能で、取り消せる。**課の承認フローとは完全に独立**とし、
  部承認後に課が改定しても部承認は残る。

## 結果

- 予算の単一責任(課が持つ)を保ちつつ、部単位の比較・承認を提供できる。
- 部承認は課改定を自動追従しない(独立が要件なので許容。最新に合わせたいときは部を承認し直す)。
- 部集計を課予算の変更と独立に実装でき、`DepartmentBudgetService` を無変更に保てた。
