# ADR-0005: 課の区分合計は常に明細合計として導出する

- 状態: Accepted
- 日付: 2026-07-11
- 関連: requests/2026-07-11(論点3「課の直接入力」→ 案件明細の合計のみとする)

## 背景

「売上高・加工費・外注費は案件別の詳細計画を立案し、その合計が課の区分合計」という要件があった。
課レベルで区分合計を直接入力できると、明細の合計と課合計が食い違い、
損益や差異の整合性が崩れるリスクがある。

## 決定

- 課の区分合計(`CategoryTotal`)は**ヘッダに金額を持たず、常に明細の合計として導出**する。
- これにより課レベルの直接入力を**構造的に不可能**にする(API・モデルに入口を作らない)。
- 期間費用も費目別明細の合計とする。

## 結果

- 「課の区分合計 = 明細合計」が破れない不変条件になる。
- 明細を持たない区分の課合計は 0。ざっくり課合計だけを入れる運用はできない(案件明細の登録が必要)。
- **この構造(ヘッダに合計を持たない)を崩さない**。
