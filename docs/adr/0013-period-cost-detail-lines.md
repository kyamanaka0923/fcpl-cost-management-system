# ADR-0013: 期間費用は費目内を明細名で細分できる(費目一括との排他)

- 状態: Accepted
- 日付: 2026-07(Issue #7)
- 関連: ADR-0003(金額のみ)、ADR-0005(区分合計=明細合計)、ADR-0009(月次入力)

## 背景

期間費用はこれまで費目ごとに1金額(費目一括)だった。しかし「ライセンス費」のように
1費目の内訳(AWS / GitHub / …)を計画・実績で分けて把握したいという要望があった(Issue #7)。
一方で「人件費」のように細分不要な費目は、従来どおり1金額で入力できる必要があった。

## 決定

- 期間費用の明細に**明細名 `PeriodDetail`(自由入力の文字列)**を追加し、費目内をさらに細分できるようにする。
  - `PeriodDetail == null` = 費目一括(従来どおり)。`!= null` = 明細。マスタは作らず自由入力(trim・空は null)。
  - 明細キーは (期間費用, 費目コード, 明細名)。**1費目内で費目一括と明細は併用不可**
    (`DepartmentBudget.EnsurePeriodModeConsistent` が二重計上を防ぐ)。費目合計 = 明細の合計(ADR-0005 を維持)。
  - 明細名は期間費用専用(案件別区分には指定不可)。各明細は月次入力(ADR-0009)にも対応。
- 実績も `PeriodDetail` を任意で持てる。**計画にない明細名でも計上でき、分析では「予定外」**として表示する
  (案件別の予定外と同じ挙動)。差異・比較のキーに明細名を含める。
- 永続化: `department_budget_lines` / `actual_entries` に `period_detail` 列を追加。
  前者は UNIQUE 制約に含めるためテーブルを作り直す(FK OFF で create-new→copy→drop→rename。ADR-0007)。

## 結果

- 費目内の内訳を計画・実績・差異で追える。細分不要な費目は従来どおりで、既存の使い勝手を壊さない。
- 明細名はマスタ管理しない自由入力のため表記ゆれは利用者責任(候補提示で緩和)。マスタ化が必要になれば本 ADR を更新する。
- 集計・損益・部集計は半期粒度・費目合計のままで、明細は内訳にとどまる(ADR-0002/0009 の方針と整合)。
