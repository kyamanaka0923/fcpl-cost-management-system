## 背景・目的

(なぜこの変更が必要か)

考えていた総合原価管理の管理単位と異なるため


## 変更したいこと

(現状 → 変更後 を具体的に)

プロジェクトという単位で予算策定の単位になっているが、課の単位で予算策定する

策定単位は、年度の上期・下期　ごとに策定する。

課の予算サマリとして見るときは以下の構成で参照する

- 売上高
- 加工費
- 外注費
- 期間費用

売上高、加工費、外注費は、さらに案件ごとの詳細計画を立案できる
案件ごとの詳細計画を合計したものが、課の売上高・加工費・外注費である。

期間費用は、以下の必要な費用の合計とする。

- 人件費
- ライセンス費


## 影響範囲(変更プラン)

<!-- Claude が現行実装を調査して記載(2026-07-11)。ほぼ全レイヤに及ぶ再構築になる -->

### 全体像

管理単位が「プロジェクト」→「課 × 半期(年度の上期/下期)」に変わり、
プロジェクトは予算策定の起点ではなく **明細の内訳次元(案件)** に降格する。
集約の軸が変わるため、リネームでは済まず予算・実績・分析・画面の全面改修になる。

現行の絶対ルールのうち以下は新モデルでも維持する:

- 明細は金額のみ(数量×単価なし)
- 承認済み予算は編集不可、改定は新バージョン(Draft→Approved→Superseded)
- 明細キーの Upsert 方式、実績の複数計上+分析時合算

「売上と原価は品目名の緩い結合」は、新モデルでは **案件名による結合** に置き換わる見込み
(売上高・加工費・外注費がいずれも案件別内訳を持つため)。

### ドメインモデル

- **新規: 課(Department)集約** — コード・名称のマスタ
- **新規: 半期(FiscalHalf)値オブジェクト** — 年度 + 上期/下期。
  既存の AccountingPeriod(年月)は明細の時間粒度として残す場合、
  「年月が半期の範囲内か」の検証を追加
- **Project → 案件へ再定義** — 予算策定単位ではなくなる。課に属する明細の内訳次元
- **CostPlan / RevenuePlan → 課別半期予算(DepartmentBudget)へ再構成**
  - 集約ルートの識別: (課, 年度, 半期) ごとにバージョン管理(現行の承認フローを踏襲)
  - 区分: 売上高 / 加工費 / 外注費 → **案件別明細**(案件, 年月, 金額)。
    「課の区分合計 = 案件明細の合計」を不変条件とする
    (現行の「品目別合計 = 全体」テストパターンを踏襲)
  - 期間費用 → **費目別明細**(人件費 / ライセンス費, 年月, 金額)。案件次元なし
- **実績(ActualCost / ActualRevenue)** も同じ軸(課 × 半期 × 区分 × 案件 or 費目 × 年月)へ変更
- **分析サービス(差異・損益・版間比較)** は課 × 半期を軸に、区分別集計 + 案件別内訳へ改修

### API

ほぼ全面変更。現行は全エンドポイントが `/api/projects/{id}/...` 起点(約30本)。

- `/api/departments` CRUD + `/api/departments/{id}/budgets?year=&half=` 起点に再編
- 予算明細の Upsert / Delete / Approve、実績、差異・比較・損益は現行の形を踏襲しつつ軸を変更
- 案件マスタの CRUD(案件をマスタ管理する場合)
- 費目マスタ API は期間費用の費目用に縮小

### 画面

全ページ影響(現行8ページ + ルーティング)。

- ProjectListPage → 課一覧(+ 年度・半期の選択)
- ProjectDetailPage → 課の半期予算サマリ(売上高・加工費・外注費・期間費用の4区分)
- PlanEditPage / RevenuePlanEditPage → 区分別の予算編集(案件別明細 + 期間費用明細)
- ActualsPage / RevenueActualsPage / VariancePage / ComparisonPage → 軸を課 × 半期に変更
- ルーティングを `/departments/:id/...` に再編

### 費目マスタ/DBスキーマ

- 新テーブル: `departments`(+ 案件をマスタ化する場合は projects を案件テーブルとして再定義)
- `cost_plans` / `revenue_plans` → 課ID・年度・半期を持つ予算テーブルへ再構成
- 明細テーブル: 区分 + 案件 + 年月 + 金額(期間費用は費目 + 年月 + 金額)
- 実績テーブルも同様に軸変更
- 費目マスタ: 現行8費目(材料費/労務費/間接費/経費)→ 期間費用の費目(人件費・ライセンス費)に整理。
  加工費・外注費は費目ではなく **固定区分に昇格** する想定
- 既存データの自動移行(冪等)は現行パターンで実装可能だが、
  「プロジェクト → 課」は機械的に対応付けできないため移行方針の確認が必要(下記論点1)

### 設計上の論点(実装前に確認したい)

1. **既存データの扱い**: 新スキーマで作り直すか、既存プロジェクトを「既定の課」の案件として移行するか
→　新スキーマで作り直す
2. **案件の管理方法**: マスタとして課に属させるか、現行の品目名と同様の文字列(緩い結合)とするか
→　マスタとして課に属する
3. **課の直接入力**: 案件詳細が未策定の区分について、課レベルの計画値を直接入力できるようにするか、
   それとも常に案件明細の合計のみとするか(「詳細計画を立案できる」の解釈)
→　案件明細の合計のみとする。
4. **明細の時間粒度**: 半期内の年月別か、半期一括の金額か
→　半期一括の金額
5. **期間費用の費目**: 人件費・ライセンス費の固定2種か、費目マスタで拡張可能にするか
→　費目マスタで拡張可能にする
