1. このガイドについて

E2E テストは、システムを外側から操作して、部品のつながりまで含めて正しく動くことを確かめるテストです。このリポジトリには 2 種類あります。

種類ファイル件数何を通して確かめるか
API E2EApiJourneyTests.cs6HTTP リクエストを送り、ルーティング・JSON 変換・エラーの HTTP ステータス変換・DB 保存までを通しで確認する
ブラウザE2Ejourney.spec.ts11実際のブラウザ(Chromium)で画面を操作し、表示まで含めて確認する

ほかのテストとの役割分担

E2Eつながりと表示

API E2E は「HTTP のつながりと数値の正しさ」、ブラウザE2E は「画面の操作と表示」を確認します。代表的な業務の流れをたどるのが役目で、ルールの細かい組み合わせまでは網羅しません。

それ以外業務ルールの網羅

業務ルールの細かい組み合わせは、Application 層のテスト、プロパティベーステスト(CsCheck)、Gherkin シナリオ(Application.Tests/Features/*.feature)が受け持ちます。

3. API E2E

3.1 仕組み

  • 起動: ApiFixture(WebApplicationFactory<Program>)が WebApi をテストのプロセス内でまるごと起動します。ネットワークポートは使いません。
  • DB: テストごとに一時 SQLite ファイルを作り、ConnectionStrings:Default を差し替えます。テスト終了時に削除するので、テスト同士が影響しません。
  • 通信: HttpClient で /api/... を呼び、ステータスコードと JSON の値を確認します。
  • 実行日に左右されない: 半期は "2026-H1" と明示しています。

3.2 業務フロー全体

計画策定から実績入力そして計画変更までの一連の業務フローが動作する

業務の流れを 1 本のテストで最初から最後までたどります。数値は 2 章の表のとおりです。

  1. 計画策定: 部・課・案件 A/B を登録し、2026 年度上期の予算(v1)に明細 5 件を入れる。区分合計(売上高 300 万・加工費 140 万・外注費 70 万・期間費用 30 万)と計画損益 60 万を確認し、承認して状態が Approved になることを確認する。
  2. 実績入力: 実績 5 件を計上する。
  3. 分析: コスト差異 +5 万・売上差異 0、差異明細に案件名「案件A」が出ること、課全体の実績損益 55 万と案件A の実績損益 62 万を確認する。
  4. 計画変更: 改定版(v2)を作ると明細 5 件が引き継がれる。加工費を 150 万に変えて承認すると、v1 が Superseded(失効)になり、バージョン比較で加工費 +10 万が出て、差異分析の基準が v2 に切り替わる。
  5. 部の予実サマリ: 部の計画売上 300 万、課が「承認済み予算あり」、全課が承認済みなので部承認が可能で、まだ未承認であることを確認する。
  6. 部承認: 承認すると isApproved が true になる。課がさらに改定・再承認しても部承認は残る(部と課の承認は独立)。取り消すと未承認に戻る。

3.3 費目マスタの拡張

費目マスタを拡張して期間費用に利用できる

シード済みの費目「人件費(PERSONNEL)」「ライセンス費(LICENSE)」があることを確認します。そのうえで新しい費目「教育研修費(TRAINING)」を追加し、予算の期間費用に 25 万で登録できることを確認します。

3.4 エラー応答

業務エラーが、正しい HTTP ステータスと日本語メッセージで返ることを確認します。

テスト操作期待する応答
存在しないリソースは404とエラーメッセージを返す存在しない課 ID を取得する404 「見つかりません」
ドメインルール違反は400とエラーメッセージを返す明細のない予算を承認する400 「承認できません」
不正な半期の形式は400を返す"2026-04" で予算を作る400 「半期の形式が不正です」
未承認の課がある部は承認できず400を返す予算のない課がいる部を承認する400 「未承認の予算がある課」

4. ブラウザE2E

4.1 仕組み

  • 起動: playwright.config.ts の webServer で、バックエンド(dotnet run、ポート 5100)とフロントエンド(Vite、ポート 5173)を自動で起動します。
  • DB: 実行 1 回ごとに一時 SQLite を 1 つ使い、11 件のテストで共有します。
  • データの衝突回避: 部コードなどに suffix(現在時刻から作る値)を付けます。同じ DB で再実行しても重複しません。
  • 実行順: mode: 'serial' で上から順に実行します。
  • 要素の見つけ方: ラベル(getByLabel)やボタン名(getByRole)など、利用者に見える名前で探します。

4.2 前半 4 件(つながった流れ)

前半 4 件はデータを引き継ぎ、2 章の数値の流れを画面操作で再現します。

①計画策定部・課・案件・予算 v1 を作って承認
部・課・案件・予算
②実績入力実績 5 件を計上
予算と実績
③分析差異と損益を表示
①の予算 v1
④計画変更改定版 v2 を承認・比較
① 計画策定部と課を登録し予算編集で案件別に金額を入力して承認できる
  • トップ画面で部を登録し、部詳細で課を登録し、課詳細で「当初予算」のドラフトを作る。
  • 予算編集画面の中で案件 A・B を追加し、案件 × 区分の表のセルに金額を入れる(セルから離れると自動保存)。
  • 案件A の粗利率 30.0% を確認する。人件費 30 万を入れると、売上高 300 万と計画損益 60 万のタイルが表示される。
  • 「この予算を承認する」で「承認済」になる。
  • 部詳細で粗利率 20.0% と課ごとの予算比較の表を確認する。予実サマリタブに切り替え、部予算を承認し、取り消すと「未承認」に戻ることを確認する。
② 実績入力区分ごとに案件別・費目別の実績を計上できる
  • 課詳細の「実績入力」で、区分・案件(期間費用なら費目)・金額を選んで計上する。これを 5 件行う。
  • 計上が終わると金額欄が空になる。次の計上に進む前にそれを待つ。連続で送信すると処理が競合する問題への対策。
③ 分析区分別の予実差異と案件別の損益が表示される
  • 予実差異タブで、コスト予算 ¥2,400,000、差異 ¥+50,000、加工費明細の「案件A」を確認する。
  • 損益タブで、案件A の実績損益 ¥620,000、「期間費用(課共通)」の行、課全体の実績 ¥550,000 を確認する。
④ 計画変更改定版の承認で旧バージョンが失効しバージョン比較で増減を確認できる
  • 「上期見直し」のドラフトを作り、案件A の加工費セルを 150 万に変えて承認する。
  • 予算バージョン一覧に「失効」バッジが出ることを確認する。
  • バージョン比較タブで加工費の増減 ¥+100,000 を確認する。

4.3 後半 7 件(独立した機能)

多くは専用の部・課を新しく作るので、前半の結果に影響されません。

テスト確認すること
⑤ 費目マスタ費目マスタ画面で追加した費目(旅費交通費E2E)が、課の予算編集の期間費用行に出る。予算編集画面には費目を追加するフォームがない。
⑥ 案件コード同じ部の 2 つ目の課で、1 つ目の課と同じ案件コードを登録してもエラーにならない(コードの一意性は課ごと)。
⑦ 案件編集登録済みの案件のコードと名称を後から変更できる(PJE-1「編集前案件」→ PJE-2「編集後案件」)。
⑧ エラー表示同じ課で案件コードを重複させると、画面の隅にエラーのトーストが出て「案件コード」を含む。×ボタンで閉じられる。
⑨ 月次入力月次入力ダイアログで 1 か月目 100 万・2 か月目 50 万を入れると、半期合計 ¥1,500,000 が自動計算される。保存後、行に月次バッジが付き、売上高タイルも 150 万になる。
⑩ 期間費用の明細ライセンス費に明細 AWS 30 万・GitHub 20 万を追加すると、小計と期間費用タイルが 50 万になる。費目ごと・全体の折りたたみと展開、明細名の変更(AWS → AWS本番、金額は保持)、GitHub の削除で期間費用が 30 万に減ることも確認する。
⑪ 期間費用の切り替えライセンス費を費目一括で 40 万入れた後に明細「AWS」25 万を追加すると、明細の入力に切り替わり、期間費用は 25 万に置き換わる。

⑨ が実行日に左右されない理由: 画面の初期半期は実行日で決まります(4〜9 月は上期、10〜3 月は下期)。そのため月次の入力欄は「4月」などの月名ではなく、半期内の位置(1 か月目・2 か月目)で指定しています。

5. 読み方と注意点

連鎖して失敗する: ブラウザE2E の前半 4 件はデータを引き継ぐので、① が失敗すると ②〜④ の失敗は二次的なものです(実行されずに「did not run」になることもあります)。原因は最初に失敗したテストで調べます。

E2E では確認していないこと(ほかのテストで確認済み)

確認していない範囲内容どこで確認しているか
ブラウザE2E実績の削除Application 層のテスト
ブラウザE2E計画にない明細名の実績(予定外)の表示Application 層のテスト、Gherkin「予実差異と損益」
ブラウザE2E部承認ができないときのエラー表示API E2E、Gherkin「部の予実と承認」
API E2E月次入力・期間費用の明細名Application 層のテスト、ブラウザE2E ⑨⑩⑪

6. 実行方法

API E2E

cd backend

ブラウザE2E

cd frontend
npx playwright install chromium   # 初回のみ
npm run test:e2e
