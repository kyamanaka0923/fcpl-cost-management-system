# 工場の実装のポリシー

Software-Factory workflow の [D] 実装(implement)と [E] 検証(code-review)で使う、コードとテストの判断基準。
implement はこの基準を満たすように書き、code-review はこの基準に反するものを「直す」の指摘にする。
細かい手順と規約は、知識「実装の規約」「テストの規約」「ドメインの規約」「DB スキーマ変更の手順」にある。

## 原則

| 原則 | 基準 |
|------|------|
| テストは仕様から導く | 処理ルールの具体例の各行と、この Issue の要件を指す `.feature` のシナリオが、すべてテストになっている。コードを書いてからテストを合わせない。実装の定数をテストの期待値にしない |
| 仕様を決めない | 仕様にないことを決めなければ進めないときは、止めて「要件の穴」として報告する。自分で決めて進めない |
| 決定事項を蒸し返さない | 知識「ドメインの規約」の決定事項(廃止済みのもの)を復活させない・作り変えない |
| 守りを弱めない | アーキテクチャテスト・アナライザ・CI の検査を、通すために弱めない |
| 小さく足す | 依存のライブラリ、新しいステップ、手書きの型を、既存のもので足りるのに増やさない |

## 直す(REJECT)

| 状況 | 判定 |
|------|------|
| 処理ルールの具体例の行、またはこの Issue の要件を指すシナリオに、対応するテストがない | 直す |
| この Issue の要件を指すシナリオに `@未実装` が残っている、またはシナリオの文・ステップの言い回しを変えた | 直す |
| シナリオが Skipped になる(未定義のステップ、キーワードの種類の不一致) | 直す |
| テスト名が日本語の文になっていない | 直す |
| 廃止済みの決定事項を復活させた(数量 × 単価、売上と原価の別承認、案件のライフサイクルの状態、原価要素の分類 など) | 直す |
| 区分合計を明細以外から作る、承認済み予算を改定版以外で変える、集計を月次の粒度でする | 直す |
| 「有利/不利」という語をコード・画面・文書・テストに書いた | 直す |
| ドメイン層が外側の層に依存する。集約に公開セッターを置く。`sealed`・`readonly record struct` の規約を外す | 直す |
| アーキテクチャテストの固定値を、集約・ポートの増減に合わせずに放置した。またはテストを弱めた(ポジティブコントロールを消すなど) | 直す |
| 不変条件をドメイン層の外だけで確かめている。違反を `DomainException`(日本語)以外で返している | 直す |
| アナライザの警告を抑制属性で散らして黙らせた。`.editorconfig` に理由なしでルールを外した | 直す |
| DTO・エンドポイントを変えたのに、`docs/api/openapi.json` と `frontend/src/api-schema.d.ts` を再生成していない。または仕様の OpenAPI と一致しない | 直す |
| フロントに手書きの API の interface を足した。React・Router 以外の依存を足した | 直す |
| スキーマの変更で、現世代のデータを消す移行をした。移行が冪等でない。`SchemaResetTests` と同じ形のテストがない | 直す |
| SQL の文字列に値を埋め込んだ(パラメータバインドでない)。秘密情報をコード・ログ・テストに書いた | 直す |
| 知識「実装の規約」の「ドキュメントの同期」に当たる変更なのに、該当する文書を直していない | 直す |
| クラス・メソッドに `<summary>` がない。フロントの型・関数・コンポーネントに JSDoc がない | 直す |
| 持ち場(`impl/` の `ROLES`)の外のファイルを変えた。`requirements/`・`knowledge/`・`specs/`・`requirements/screens/approved/` を変えた | 直す |

## 確かめる(人への問いにする)

| 状況 | 扱い |
|------|------|
| 既存のステップで書けそうなのに、新しいステップを足した | 既存のステップの候補を挙げて問う |
| 速いスコープで確かめられることを、遅いスコープ(E2E)に書いた | 置き場所の候補を挙げて問う |
| コミット前のチェックリストの一部を、環境の都合で動かせなかった | 「未確認」と理由を書く。未確認だけを理由に差し戻さない |
