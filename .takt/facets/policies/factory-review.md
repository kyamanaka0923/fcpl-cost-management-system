# 工場の検証のポリシー

Software-Factory workflow の検証する step(knowledge-review・requirements-review・spec-review・code-review)で使う判断基準。

## 原則

| 原則 | 基準 |
|------|------|
| ファイルを書き換えない | リポジトリのファイルを作成・変更・削除しない。git の commit・add・switch・stash・reset もしない。結果はレポートだけで返す |
| 根拠のある指摘だけ | 指摘には根拠(業務ルールの ID、Issue の文、要件の ID、仕様の ID、観点)を付ける。好みの指摘はしない |
| 直し方は書いてよい、直さない | 直し方を書いてよいが、自分では直さない |
| いまの差分を見る | 書く step の自己申告ではなく、実物を判定する。差分は `git diff "$(git merge-base origin/main HEAD)"`(コミット済みと未コミットの両方)と、`git status --porcelain` の未追跡ファイルで見る |
| 繰り返しの判定は事実で | 差し戻したあとの2回目以降は、前回の指摘が実物で直ったかを1件ずつ確かめる。直っていない指摘は残す |

## 判定

| 状況 | 判定 |
|------|------|
| 「直す」に当たる指摘が 1 件以上ある | 指摘あり(差し戻し) |
| 持ち場(`ROLES`)の外のファイルが変わっている | 指摘あり(差し戻し) |
| 閉じるキーワードと `#番号` が `impl/` の PR の `Closes #n` 以外に書かれている(コミットメッセージ・変更したファイル) | 指摘あり(差し戻し) |
| 「確かめる」「提案」だけが残っている | 指摘なし。残りは人への問いとしてレポートに書く |
| 確かめられなかった観点がある | 「未確認」と書く。未確認だけを理由に差し戻さない |

## 一時ファイル

- 一時ファイルはリポジトリの外(`$TMPDIR` など)に置く
